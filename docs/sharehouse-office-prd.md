# 쉐어하우스 오피스 PRD

## 1. What — 한 줄 정의

쉐어하우스 정산 관리 어드민은 매달 발생하는 공용 관리비 지출을 입력하면 입주자별 정산 금액(월 사용료 + 관리비)을 자동으로 계산해주는 쉐어하우스 운영자 전용 관리 도구입니다.

## 2. 메인 사용 시나리오 (3개)

1. 운영자가 매달 초, 그 달에 발생한 관리비 항목(가스비, 전기세, 수도세, 인터넷, 공용물품)을 하나씩 입력하면, 시스템이 인원 변동과 이용일수를 반영해 입주자별 관리비를 자동 계산한다.
2. 운영자가 새 입주자를 등록(이름, 방, 계약기간, 월 사용료, 할인 여부/금액)하면, 계약기간에 따라 해당 입주자가 정산 대상에 자동으로 포함된다.
3. 중도입퇴실자가 발생하면, 운영자가 계약기간(입실일 또는 퇴실일)을 수정해 월 사용료와 관리비가 실거주일수 기준으로 자동 재계산된다.

## 3. Who — 타겟 사용자

- **페르소나**
  - 쉐어하우스 1개 지점 단독 운영
  - 매달 엑셀, 노션 등으로 수기 관리비 정산 진행 중
  - 향후 5개 이상 지점으로 확장 계획 보유
  - 향후 총무 역할의 보조 인력 운영 계획 보유
- **핵심 페인 포인트**
  - 중도입퇴실자 발생 시 일할계산 번거로움, 실수 발생 가능성 존재
  - 정산 화면 캡쳐 후 입주자 발송 과정 번거로움 (노트북은 그나마 용이, 외출 중 휴대폰 처리는 어려움) → 반응형(모바일 대응) 화면 필요
  - 노션 사용 시, 유저의 database 필터 수정을 막을 방법 없음 (관리비 전체 DB에 매달 필터를 씌워 공유하는 방식이라 필터 변경/훼손 리스크 존재)
- **성공 정의**
  - 정산 소요 시간 단축
  - 계산 실수 발생 0건 유지

## 4. Behavior — 화면별 명세

### 화면 1: 월별 정산 대시보드 (URL: /settlements/:year-:month)

**진입 조건**: 구글 로그인 필수. 미인증 상태로 접근 시 로그인 화면으로 리다이렉트. 로그인 후 특정 연/월을 선택해서 진입 (기본값: 이번 달)

**UI 요소**:

- 상단: 연/월 선택 드롭다운 (예: "2026년 6월")
- 섹션 0. **공지사항**
  - 운영자가 작성한 안내문이 여러 개 누적되어 리스트 형태로 표시
  - 드래그 앤 드롭으로 순서 재정렬 가능
- 섹션 A. "총 관리비 지출 내역" 테이블
  - 컬럼: 시작일/구매일, 종료일, 항목(가스비/전기세/수도세/인터넷/공용물품, 태그 형태), 금액, 메모, 영수증 보기(이미지 첨부)
  - 하단에 합계 금액 표시
  - 행 추가/삭제/수정 가능
- 섹션 B. "입주자별 정산 결과" 테이블
  - 컬럼: 이름, 시작일, 종료일, 이용일수, 관리비(자동계산)
- 반응형 레이아웃: 모바일에서는 테이블이 카드형(행 단위 → 카드 단위)으로 전환되어 조회 가능

**사용자 액션 & 예외 처리**:

- "공지사항 추가" 클릭 → 제목/본문 입력 → 저장 시 리스트에 누적 표시
- 공지사항 드래그 → 순서 즉시 반영 및 저장
- "새 지출 항목 추가" 클릭 → 항목(가스비/전기세/수도세/인터넷/공용물품) 선택
  - 공용물품은 여러 행 등록 가능
  - 가스비/전기세/수도세/인터넷처럼 월 1건 성격의 항목은, 이미 이번 달에 입력된 항목일 경우 항목 선택 단계에서 드롭다운에 비활성화(또는 "입력됨" 표시)로 노출되어 애초에 중복 선택이 불가능하도록 처리
  - 항목 선택 후 시작일/종료일/금액/메모/영수증 이미지 입력
  - 영수증 이미지 업로드 실패(용량 초과, 형식 오류 등) → "이미지를 업로드할 수 없습니다 (용량/형식 확인)" 에러 표시
- 지출 항목 저장 → 섹션 B의 입주자별 관리비 자동 재계산 및 반영
  - 관리비 항목이 하나도 없는 상태 → "아직 입력된 지출 항목이 없어요" 안내 표시
  - 입주자가 0명인 상태 → "정산할 입주자가 없습니다" 안내 표시 (0으로 나누기 방지)
- "게시(Publish)" 버튼 클릭 → 해당 월 정산 데이터가 화면 3(관리비 조회 화면)에 노출되도록 상태 전환
  - 게시 전 상태에서 "정산 결과 발송" 시도 → "게시 후 발송할 수 있습니다" 안내 표시
- "정산 결과 발송" 버튼 클릭 → 확인 모달 표시 → 확인 시 알림 발송 트리거 (※ 실제 발송 로직은 Out of Scope, UI/트리거 구조만 반영. 운영자가 버튼을 눌러야만 트리거되는 수동 방식)

**다음 화면**: 입주자 이름 클릭 시 → 화면 2 (입주자 관리)

---

**계산 로직 (섹션 B, 입주자별 관리비)**

지금까지 확정된 계산 원칙은 다음과 같다.

```
1) 항목별 "유효기간(1일당 단가 계산의 분모)" 결정
   - 청구서에 시작일/종료일이 명시된 항목(가스비, 전기세 등): 명시된 기간 그대로를 유효기간으로 사용
     (정산월로 자르지 않음. 실제 입주자 부담액은 이후 단계에서 거주 여부에 따라 결정되므로,
      이 기간 중 거주하지 않은 입주자는 자동으로 부담액 0)
   - 정산월 전체를 쓰는 항목(수도세, 인터넷): 정산월 1일~말일
   - 공용물품(구매일만 있고 종료일 없음):
     · 그 달 첫 인원변동 이전 구매 → 정산월 1일~말일
     · 그 달 인원변동 중간에 구매 → 구매일~정산월 말일 (구매 이전 서브 기간 제외)
     · 그 달 마지막 인원변동 이후 구매 → 구매일~정산월 말일

2) 유효기간을 "입주자 구성(인원)이 바뀌는 시점" 기준으로 서브 기간으로 분할

3) 1일당 단가 = 항목 금액 ÷ 유효기간 전체 일수 (반올림 없이 정밀 계산)

4) 서브 기간별 1인당 배분액 = 1일당 단가 × 서브 기간 일수 ÷ 그 서브 기간의 실제 거주 인원수
   (반올림 없이 정밀 계산 — 거주하지 않은 입주자는 자연히 해당 서브 기간 계산에서 제외)

5) 입주자별 "항목별 최종 합산액" = 자신이 실제 거주했던 서브 기간들의 배분액 합
   → 이 시점에 원 단위로 반올림 (최종 출력값). 서브 기간 단계에서는 반올림하지 않음

6) 입주자별 관리비 총액 = 모든 항목의 (반올림된) 합산액의 합

7) 반올림 후 "입주자별 금액의 합"이 "항목 실제 총액"과 차이 나더라도 별도 보정하지 않음
   (해당 차액은 운영자가 부담. 최대잔여법 등 보정 로직 미적용)
```

이용일수 계산: 이용일수 = 해당 월의 날짜 범위와 입주자 계약기간의 교집합 일수
(예: 계약기간 1/15~~7/15인 경우 → 1월 이용일수 17일, 2~~6월은 각 월 전체 일수, 7월 이용일수 15일)

### 화면 2: 입주자 관리 (URL: /tenants)

**진입 조건**: 구글 로그인 필수. 사이드 메뉴에서 "입주자 관리" 클릭, 또는 화면 1에서 입주자 이름 클릭

**UI 요소**:

- 입주자 리스트 테이블: 이름, 배정된 방, 계약기간(시작일~종료일), 월 사용료 금액, 할인(사유+금액)
- "새 입주자 등록" 버튼

**사용자 액션 & 예외 처리**:

- "새 입주자 등록" 클릭 → 입력 폼(이름, 방, 계약기간(시작일~종료일), 월 사용료, 할인 여부/금액) → 저장 시 계약기간에 따라 해당 월(들) 정산 대상에 자동 반영
  - 필수값: 이름, 방, 계약기간, 월 사용료 (할인 여부/금액은 선택 입력)
  - 필수값 누락 시 → "필수 항목을 입력해주세요" 에러 표시
- 기존 입주자 클릭 → 정보 수정
- 계약기간(시작일 또는 종료일) 수정 → 저장 시 화면 1의 해당 월 정산에서 이용일수 및 금액 자동 재계산 (입실일·퇴실일 수정 모두 동일하게 적용)
  - 종료일이 시작일보다 빠른 경우 → 저장 불가, "종료일은 시작일 이후여야 합니다" 에러 표시

**다음 화면**: 없음 (독립 화면, 필요 시 화면 1로 돌아감)

### 화면 3: 관리비 조회 화면 (URL: /view/:year-:month)

**진입 조건**: 인증 불필요. 운영자가 공유한 링크로 누구나 접속 가능. 단, 운영자가 게시(Publish)하지 않은 월의 데이터는 조회 불가

**UI 요소**:

- 공지사항 리스트 (화면 1에서 정렬한 순서 그대로, 읽기 전용)
- 해당 월 "입주자별 정산 결과" 테이블 (이름, 시작일, 종료일, 이용일수, 관리비) — 읽기 전용
- "공유하기" 버튼 (링크 복사 등, 학부모 등 제3자와 공유 목적)
- 모바일 카드형 레이아웃 우선 대응

**사용자 액션 & 예외 처리**:

- "공유하기" 클릭 → 현재 화면의 URL(`/view/:year-:month`) 복사 또는 공유 시트 노출
- 게시되지 않은 월에 접근 → "매월 25일 이후에 게재되어요" 안내 문구 표시
- 존재하지 않는 월 경로로 접근 → "해당 정산 정보를 찾을 수 없습니다" 안내 화면 표시

## 5. Out of Scope — 이번 버전에 만들지 않는 것 (MVP 이후 설계 참고용)

- 전체 캘린더 연동(구글 캘린더, 당번/점검 일정 등)
- 현금영수증 발급
- 납부 상태 체크(완료/미납 표시)
- 자동 알림 발송(매달 25일 자동 발송 등): 현재는 운영자가 "발송" 버튼을 눌러야만 트리거되는 수동 방식
- 네이티브 앱(iOS/Android): 반응형 웹으로 모바일 대응
- 멀티 유저 권한 관리(총무 등 제한된 권한 계정): 데이터 모델 설계 시 "사용자" 개념만 분리해 추후 확장 가능하도록 고려
- 멀티 지점 관리(5개 이상 지점 동시 운영): 데이터 모델에 "지점 ID" 필드만 미리 포함, UI는 1개 지점 기준으로 구현
- 기간별 가격표 & 할인이벤트 관리 페이지: 향후 이 페이지가 생기면 화면 2에서 "방 선택 시 월 사용료 자동 입력", "할인 이벤트 드롭다운 선택" 형태로 연동 가능

## 6. Tech Stack

- Frontend: Next.js
- Backend: Supabase (Postgres + Auth, Google OAuth)
- Hosting: Vercel
- 디자인: Tailwind CSS, 반응형(모바일 대응) 필수, 심플하고 정보 밀도 높은 테이블 중심 UI (운영자 화면), 모바일 우선 카드형 레이아웃 (관리비 조회 화면)
- 코드 컨벤션: [토스 Frontend Fundamentals](https://frontend-fundamentals.com/code-quality/) 원칙을 참고 문서로 채택. 실제 강제/적용은 별도 스킬(skill)로 구현 예정 (PRD 승인 후 착수)

**참고 사항**

- Supabase → AWS 마이그레이션: DB(Postgres)는 표준 포맷이라 이전이 비교적 수월하며, Storage(영수증 이미지)도 S3로 옮기기 쉬움. Auth(특히 구글 로그인만 사용하는 경우)도 상대적으로 무리 없는 편. MVP는 Supabase로 빠르게 검증 후, 필요 시 이전하는 전략이 합리적
- 백엔드 API 명세(OpenAPI 등): 1인 풀스택 + Supabase 클라이언트 직접 쿼리 구조이므로 현재는 불필요. 추후 알림 발송 등 외부 연동을 위한 커스텀 서버 엔드포인트가 생기는 시점에 최소한으로 문서화 권장
- 아키텍처: 화면 단위 폴더 구조, Supabase 쿼리는 도메인별 함수(`lib/settlements.ts`, `lib/tenants.ts` 등)로 분리, 계산 로직(이용일수/일할계산/관리비 계산)은 UI와 분리된 순수 함수로 작성 권장

## 7. Success Criteria — 완성 기준

- [ ] 화면 1, 2는 구글 로그인 없이는 접근할 수 없다
- [ ] 관리자가 특정 월의 관리비 지출 항목(가스비/전기세/수도세/인터넷/공용물품)을 입력/수정/삭제하고 영수증 이미지를 첨부할 수 있다
- [ ] 이미 입력된 월 1건 성격 항목(가스비 등)은 항목 선택 단계에서 중복 선택이 차단된다
- [ ] 공지사항을 여러 개 등록하고 드래그로 순서를 바꿀 수 있다
- [ ] 입주자별 관리비가 확정된 계산 원칙(항목별 유효기간 → 인원변동 기준 서브 기간 분할 → 정밀 계산 → 항목 합산 시점 1회 반올림)에 따라 자동 계산되어 표시된다
- [ ] 신규 입주자를 등록하면 계약기간에 따라 해당 월 정산 대상에 자동으로 포함된다
- [ ] 계약기간(입실일/퇴실일)을 수정하면 이용일수와 관리비가 자동 재계산된다
- [ ] 한 화면(월별 정산 대시보드)에서 공지사항, 총 관리비 지출 내역, 입주자별 정산 결과를 동시에 확인할 수 있다
- [ ] "게시(Publish)" 하지 않은 월은 관리비 조회 화면에서 "매월 25일 이후에 게재되어요" 문구가 표시된다
- [ ] 게시된 월은 인증 없이 관리비 조회 화면에서 열람 가능하고, "공유하기"로 링크를 복사/공유할 수 있다
- [ ] 운영자 화면과 관리비 조회 화면 모두 모바일에서 카드형 레이아웃으로 정상 렌더링된다
- [ ] 관리비 항목이 없거나 입주자가 0명인 경우 에러 없이 안내 메시지가 표시된다
